Status

Fuxedo is under active development and usable today for development and testing; the compatibility suite runs unmodified against Oracle Tuxedo 12.2.2 and 22.1 on every commit, which is the project's definition of "matches".

Done and verified

The ATMI client and server API (tpinit, tpcall, tpacall, tpgetrply, tpforward with flag and transaction semantics, tpreturn, tpadvertise/x with TPSINGLETON and TPSECONDARYRQ), FML32 with Oracle-compatible field ids and boolean expressions, VIEW32, XML buffers with tpxmltofml32 and BUFTYPECONV, STRING and CARRAY, tpimport/tpexport. Administration: tmloadcf, tmunloadcf, tmboot, tmshutdown, tmadmin, qmadmin, ud32, tmipcrm, crdl/crlog, the MIB classes, runtime updates (adv, unadv, suspend, resume, chgserver, changetrace), and printtrans with the offline log utilities. Operations: MSSQ sets with secondary queues, REPLYQ, automatic restart with MAXGEN/RESTART/GRACE. Transactions: multi-group two-phase commit with per-group TMS servers, a folder-based TLOG with heuristic detection, transactions across domain gateways and over workstation links. EventBroker: tpsubscribe, tppost, tpnotify, unsolicited messages with tpsetunsol/tpchkunsol, the TMUSREVT/TMSYSEVT servers, and the same on-disk subscription database format. /Q queues as folders and files with TMQUEUE and TMQFORWARD. Networking: GWTDOMAIN gateways with dmadmin, encrypted links with trust-on-first-use pins, and workstation clients via WSL and WSNADDR. Tracing: USDT probes (provider "fuxedo") plus uprobe-friendly builds, so bpftrace attaches without any fuxedo configuration. An invalid-argument hardening suite guards the API surface on both implementations. Python throughout via tuxedo-python, whose demo runs against all three homes.

Known gaps

Honest list, no asterisks: data-dependent routing (*ROUTING section) is parsed but not enforced; tpbroadcast is the one EventBroker call still missing; conversational tpconnect/tpsend/tprecv is untested end to end; event delivery to workstation clients is not routed yet; tmadmin's diagnostic surface (bbparms, dump, shmstats) is thin; FML32 indexes are not stored (a flat layout by design, at a small lookup cost). Multi-machine MP clustering is deliberately out of scope.

Roadmap

In rough order: domain-level /Q (enqueue into a queue space served by a remote domain), the remaining tmadmin surface, tpbroadcast, and deeper workstation coverage. The gap list and the API coverage matrix live in the repository, updated as items land.

Follow the project

Watch the repository for releases (GitHub emails on new ones if you watch with "all activity"), subscribe to the releases RSS feed, read the commit stream, or write to hello@fuxedo.io for the occasional project letter. Releases and their notes live on the GitHub releases page; 0.9.x is tagged and current.
