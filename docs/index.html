Fuxedo

An open source alternative to Oracle Tuxedo

Fuxedo is an open source implementation of the X/Open XATMI specification and a growing set of Oracle Tuxedo extensions. The aim is source compatibility: recompile your application against Fuxedo and run it. Configuration files keep the Tuxedo formats, so the tools you already know (tmloadcf, tmboot, tmadmin, qmadmin) work the way the manuals say they should.

The name is a wordplay on “free” and Tuxedo, and on the fuxedo itself: a one-piece suit that combines the elegance of a tuxedo with the convenience of a jumpsuit. That is roughly the engineering goal too.

Design ideas

The configuration is a file, not a database. TUXCONFIG is a small header in front of the plain UBBCONFIG text. tmloadcf parses and validates the text, then builds the bulletin board in shared memory. tmunloadcf prints the text back. Administration goes through the same MIB classes Tuxedo documents (T_DOMAIN, T_GROUP, T_SERVER), and tpadmcall works on the configuration file directly, which is how the configuration can be created programmatically from scratch, no running system needed.

System V IPC, on purpose. Fuxedo keeps the mechanics Tuxedo behavior is built around: message queues, shared memory, semaphores. Servers block in msgrcv the way Tuxedo servers do, requests carry per-service message types, and an MSSQ set is exactly what the name says: several servers, one queue. Where Tuxedo's documented behavior says a message cycles through a set until the right server takes it, Fuxedo does that too.

FML32, familiar down to the field ids. The API matches Tuxedo, field numbers and types follow the same tables, and what crosses process or system boundaries stays compatible: tpimport/tpexport payloads and compiled boolean expressions (Fboolco32 trees, memory prefixes and all) work on both sides. Inside a process each implementation keeps its own buffer layout. Nested sub-buffers included.

Queues you can ls. The /Q component stores a queue device as a directory, queues as folders, and messages as files, committed with an atomic rename. Everything is persistent, everything is visible, and qmadmin speaks the same command language as the original.

Same tests, two implementations. The compatibility suite runs unmodified against both Fuxedo and Oracle Tuxedo, so behavior matches the documentation on either side, and stays matched as the project grows.

Scriptable from Python. The tuxedo-python bindings run unchanged on top: servers, clients, the MIB administration calls, and the demo applications from the book Modernizing Oracle Tuxedo Applications with Python.
