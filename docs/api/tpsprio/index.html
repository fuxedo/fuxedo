Synopsis

#include <atmi.h>

int tpsprio(int prio, long flags);

Description

tpsprio() sets the priority attribute that rides with the application's NEXT call (pinned live: after the call is sent, the value resets to the documented 50 default). The documentation describes it as a scheduling hint; pinned live against Oracle Tuxedo 12.2.2 and 22.1, it is not: requests are still dispatched in arrival order, and the only observable effect is the attribute itself, readable inside a service with tpgprio().

The value is an opaque attribute: it is never range-checked (0, 101, and negative values are all accepted), and it has no effect on the caller's own waits.

Arguments

ArgumentDescription
prioThe attribute value. Not range-checked: any int is accepted, including 0 and negatives.
flagsTPABSOLUTE stores prio as-is; 0 (relative) adjusts the current value by prio. Any other flag fails with TPEINVAL.

Flags

FlagDescription
TPABSOLUTEStore the value as-is.
0Relative: adjust the current value (default base 50).

Any other flag fails with TPEINVAL; that is the only validation this call performs.

Errors (tperrno)

CodeDescription
TPEINVALflags is neither 0 nor TPABSOLUTE.

Notes

What actually works. Pinned against both Oracle Tuxedo 12.2.2 and 22.1 on a live domain: tpsprio() never changes dispatch order (a full request queue is still drained FIFO), the value applies to the next call only, and client-side tpgprio() reads -1 there regardless of what was set. What does travel is the attribute: tpgprio() inside a service returns the caller's priority for that call, or the documented default 50 when the caller never set one. fuxedo implements exactly that: the API contract is kept, the scheduling claim is a no-op.

Example

Full source: docs/api/examples/prio.c (build and run with make -C docs/api/examples check TUXDIR=<install>); the lines documenting tpsprio() are highlighted.

// tpsprio()/tpgprio() example: the priority attribute rides with the
// call and is readable inside the service. Values are never
// range-checked and dispatch order is unaffected - both pinned live
// against Oracle 12.2.2 and 22.1.

#include <stdio.h>
#include <string.h>
#include <atmi.h>

int main() {
  if (tpinit((TPINIT *)NULL) == -1) {
    perror("tpinit");
    return 1;
  }

  char *buf = tpalloc("STRING", NULL, 32);
  strcpy(buf, "hello");
  long len = 32;

  // sets the priority attribute carried by the next calls; flags are
  // 0 (relative) or TPABSOLUTE, the value itself is never
  // range-checked, and dispatch order is unaffected - the value is
  // an attribute readable in the service, not a scheduling knob
  if (tpsprio(77, TPABSOLUTE) == -1) {
    fprintf(stderr, "tpsprio failed: %s (%d)\n", tpstrerror(tperrno),
            tperrno);
    return 1;
  }

  // client-side: reads back the value set by tpsprio() (fuxedo) - on
  // Oracle Tuxedo it reads -1 regardless. Inside a service it returns
  // the invoking call's priority, 50 when the caller never set one
  printf("current priority: %d\n", tpgprio());

  if (tpcall((char *)"PRIO", buf, 0, &buf, &len, 0) == -1) {
    fprintf(stderr, "tpcall failed: %s (%d)\n", tpstrerror(tperrno),
            tperrno);
    return 1;
  }

  tpfree(buf);
  tpterm();
  return 0;
}
